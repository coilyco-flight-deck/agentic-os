# Mount-eligibility manifest

`agent-compose` emits a machine-readable **mount-eligibility manifest** at
`~/.config/agent-compose/mount-eligibility.json` beside the composed context it
already writes. The manifest answers one question for ward: on this host, which
repos may each harness mount? The answer is **data produced by aos, read by
ward** at compose-generation time. ward does not re-derive scope - the
eligibility decision is a read, not new judgment in the orchestrator.

## Why it lives in the composer

The rule for which repos a harness may mount (claude mounts everything, codex
only flight-deck) is the same scope logic the composer already computes when it
decides which `AGENTS.COMPOSE.md` sources compose into which harness's load
point. Re-implementing that rule in ward would be a second source of truth, free
to drift from the first. Instead the manifest reuses the composer's own
per-harness selection - scope filtering (`scopes:` intersection) and harness
filtering (`harnesses:` frontmatter) - so the two decisions cannot disagree.

## What it contains

The manifest is deterministic JSON (sorted, no timestamps) so the drift check
reproduces it byte-for-byte:

```json
{
  "banner": "generated by agent-compose ...; do not edit",
  "projects_root": "/Users/kai/projects",
  "defaults": ["/Users/kai/projects/coilyco-bridge/lore", "..."],
  "harnesses": {
    "claude": ["...absolute repo paths..."],
    "codex": ["...absolute repo paths..."]
  }
}
```

- **`projects_root`** - the workspace root the paths resolve under, honoring
  `$PROJECTS_ROOT` (`agentic_os.config.projects_root`).
- **`defaults`** - the always-on default mount set, surfaced for provenance.
- **`harnesses`** - per harness, the **complete** set of mountable repos: its
  eligible repos already unioned with the defaults, sorted and deduplicated.
  ward reads one key and needs no second merge.

## How a source becomes a mountable repo

Mount eligibility is **per repo, not per source file**. A source nested anywhere
inside a repo (`~/projects/<org>/<repo>/deep/AGENTS.COMPOSE.md`) makes that whole
repo mountable - the org and repo are the first two path components under the
projects root, mirroring the `~/projects/<org>/<repo>` workspace layout. A source
that is not under the projects tree - an out-of-repo
`~/.config/agent-compose/sources/` doctrine file, the kind a `root` may
legitimately point at - backs no mountable repo and is skipped.

## Default mount set

Three repos mount **regardless of task or harness** (epic
[#220](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/220)):

- `coilyco-bridge/lore` - agent knowledge.
- `coilyco-flight-deck/agentic-os` (aos) - doctrine plus the repo the harness
  itself is edited in.
- `coilyco-bridge/agentic-os-kai` (aosk) - operating context. aosk has no
  implementation ticket of its own but is a default mount.

They are unioned into every harness's entry so a harness with no eligible
overlay still gets them.

## Drift

The manifest is regenerated on every `agent-compose` run, written only when its
content changed (so the compose-freshen SessionStart hook stays silent on a
no-op). `agent-compose --check` - the `check-agent-compose-drift` pre-commit
hook - verifies the on-disk manifest matches a fresh computation, exactly as it
verifies `COMPOSED.md`, and prints a unified diff on drift.
