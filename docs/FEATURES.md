# Features

What `agentic-os` does. Cross-platform shell, terminal, and secret-handling for every host Kai runs. Public, generic, leak-safe by construction.

This doc describes capabilities, not files. If you want a file inventory, run `ls`.

## Inventory

- [Shell and secret handling](features-shell-secrets.md) - cross-platform zsh, agent-CLI repo gate (claude/codex/opencode refuse to launch outside a git repo), in-process SSM secret loader, Warp terminal config, GPG-without-disk-passphrases, install surface.
- **Karabiner key binding assets** - `karabiner/*.json` store complex modifications symlinked into Karabiner's assets directory: Control+Escape -> backtick, a device-scoped left_option <-> left_command swap for the external keyboard, plus a command -> control remap scoped to Microsoft Remote Desktop so Cmd hotkeys reach the remote Windows session. Install `brew install --cask karabiner-elements`, setup in [docs/repo-layout.md](repo-layout.md).
- [Agents and sessions](features-agents-sessions.md) - agent self-name, session pulse, and a project-local status-line repo-checkout tracker ([`.agentic-os/statusline.sh`](../.agentic-os/statusline.sh)) that names the `org/repo` clones on disk which are not on an expected-repos list, i.e. the strays to remove.
- [Which harness when](harness-selection.md) - the five agent harnesses (Claude, Codex, OpenCode, Aider, Goose) and three model tiers (trivial-local, capable-local, cloud), with a decision guide for picking one.
- [Test harnesses](test-harness.md) - one doc per agent probing a harness+model pairing before trusting it with real work. [Agent compatibility check](agent-compat.md) runs the daily unittest smoke; Goose also ships `ward exec goose-ask`.
- [Issue-corpus discovery index](issue-corpus.md) - `ward exec render-issue-corpus` renders the Forgejo issue corpus (every repo in `scripts/issue-corpus-repos.txt`, **open AND closed**, bodies + every comment) to one markdown file per issue under a private git mirror, so a warded container can **grep the corpus offline** to _locate_ an issue then confirm live state via `ward ops forgejo issue view`. A discovery index, not a source of truth: every file carries that disclaimer (the AGENTS.md anti-drift discipline). Incremental via `manifest.json` (skips issues whose `updated_at` is unchanged), all Forgejo I/O routes through `ward ops forgejo` (no `FORGEJO_TOKEN`), and trufflehog scans the corpus before the hourly `.forgejo/workflows/issue-corpus.yml` cron pushes the private mirror (agentic-os#297).
- [ward deployment spec bundle](ward-specs.md) - the aos-hosted `ward` deployment input bundle for the coilyco fleet. It carries the forgejo, signoz, ollama, and fleet KDL sources plus their spec locks, so ward can source the canonical deployment specs from this repo instead of carrying the bundle in-tree.
- [Cross-repo tooling and release](features-release-tooling.md) - pre-commit baseline, diagnostic helpers, Forgejo-canonical release actions.
- [dev-base container image](dev-base-image.md) - the inner-loop toolchain (uv, pre-commit, node, go, aws cli, claude, codex, goose, docker, tailscale) plus the **pre-commit / CI gate tools** (golangci-lint, trufflehog, kdlfmt) so an agent self-runs `pre-commit run --all-files` and the lint/secret jobs in-container instead of hand-fetching binaries ([agentic-os#292](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/292)) - golangci-lint + kdlfmt hand-pinned to the consuming repos' CI versions, trufflehog auto-bumped - published per release to the forgejo registry as `coilyco-flight-deck/agentic-os:<tag>`, multi-arch, pulled by tag in ward. Defaults `AWS_DEFAULT_REGION` / `AWS_REGION` to `us-east-1` and ships the `tailscale` client so a credentialed/authed container reaches SSM and the tower over the tailnet instead of failing on `NoRegion` / a missing binary ([agentic-os#286](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/286)). Bakes a **public substrate seed** (bare mirrors of the image-tier reference repos at `/opt/substrate-seed`) so a ward container warms a cold gitcache with no network. Bakes the **in-container agent self-name** (a trimmed `agent-name.sh` under `/opt` plus a policy-tier `/etc/claude-code/managed-settings.json`) so a warded explorer / headless agent self-names like a host session, uid-independently ([agentic-os#281](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/281)) - and appends the friendly **container name** in brackets when ward exports `WARD_CONTAINER_NAME`, self-suppressing on a native host so both stay format-consistent ([agentic-os#296](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/296)). Points that managed `statusLine` at a baked **[status-line composer](statusline.md)** (`statusline.sh` + a `statusline.d/` provider dir) so every warded container shows the **full segment-composed line** - agent-name, repo-tracker, and any user / repo overlay provider - not just the name row, and new providers ride the next image build to all containers at once ([agentic-os#294](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/294)). A `SessionStart` **git-identity stamp** then writes that self-name as `git config --global user.name` so a warded commit records which agent made it, leaving the load-bearing bot `user.email` ward sets at `--system` untouched for Forgejo account linking ([agentic-os#244](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/244)). A scheduled [**auto-bump**](dev-base-auto-bump.md) (`.forgejo/workflows/dep-bump.yml`, `ward exec dep-bump`) resolves each pinned tool against upstream and commits one `ARG` bump per stale tool to main, republishing `:latest` so the image stops drifting behind upstream.
- [Managed AGENTS.md pointer block](features-agents-pointer.md) - org-aware, drift-checked workspace-base pointer rendered into each repo's AGENTS.md.
- [Encoded leak guard](leak-guard.md) - pre-commit hook that rejects plaintext occurrences of awkward-leak terms (employer/partner names, private-to-public references) held as hex and decoded only in memory, so the ruleset is not itself grep-bait.
- [Context-budget report](context-budget.md) - on-demand measure of the eager startup context each harness (claude/codex/opencode) loads vs a per-harness token budget, with per-source attribution, reusing the agent-compose resolution.
- [Mount-eligibility manifest](mount-eligibility-manifest.md) - agent-compose emits `mount-eligibility.json`: per harness, the repos it may mount on this host (`~/projects/<org>/<repo>` paths plus an always-on default set), reusing the composer's scope/harness selection so ward reads the mount decision instead of re-deriving it. Drift-checked.
- [Committed ward-ops reference](ward-ops-forgejo-reference.md) - checked-in `ward ops forgejo describe` render so operator-verb names stay greppable. `ward exec gen-ward-ops-reference` regenerates it. See agentic-os#261.
- [Catalog caps reference](catalog-caps-reference.md) - the `code-comments` / `documentation-layout` numeric caps rendered straight from the validator constants by `ward exec gen-caps-reference`, so docs and skills point at one generated source instead of hand-copying a number that drifts. `check-caps-reference-drift` fails commit on a stale render, mirroring `check-seed-skills-drift`. See agentic-os#284.
- [Knowledge-base freshness program](knowledge-base-freshness.md) - grades knowledge by **decay-class** (asserted/pointer/derived) and **half-life** (fast/slow), carried inline as `<!-- freshness: as-of= half-life= -->` provenance markers. `ward freshness` parses them across tracked docs and flags any fact aged past its horizon (`-- --check`), the loud trigger a scheduled probe (`.forgejo/workflows/freshness.yml`) fails on, since knowledge rot is silent where code drift is loud. Hermetic, time-based, not a commit-path hook. See agentic-os#262.
