# Features

What `agentic-os` does. Cross-platform shell, terminal, and secret-handling for every host Kai runs. Public, generic, leak-safe by construction.

This doc describes capabilities, not files. If you want a file inventory, run `ls`.

## Inventory

- [Shell and secret handling](features-shell-secrets.md) - cross-platform zsh, agent-CLI repo gate (claude/codex/opencode refuse to launch outside a git repo), in-process SSM secret loader, Warp terminal config, GPG-without-disk-passphrases, install surface.
- **Karabiner key binding assets** - `karabiner/*.json` store complex modifications symlinked into Karabiner's assets directory: Control+Escape -> backtick, a device-scoped left_option <-> left_command swap for the external keyboard, plus a command -> control remap scoped to Microsoft Remote Desktop so Cmd hotkeys reach the remote Windows session. Install `brew install --cask karabiner-elements`, setup in [docs/repo-layout.md](repo-layout.md).
- [Agents and sessions](features-agents-sessions.md) - agent self-name, session pulse, and a project-local status-line repo-checkout tracker ([`.agentic-os/statusline.sh`](../.agentic-os/statusline.sh)) that names the `org/repo` clones on disk which are not on an expected-repos list, i.e. the strays to remove.
- [Which harness when](harness-selection.md) - the five agent harnesses (Claude, Codex, OpenCode, Aider, Goose) and three model tiers (trivial-local, capable-local, cloud), with a decision guide for picking one.
- [Test harnesses](test-harness.md) - one doc per agent probing a harness+model pairing before trusting it with real work. [Agent compatibility check](agent-compat.md) runs the daily unittest smoke; Goose also ships `ward exec goose-ask`.
- [Goose issue triage](goose-triage.md) - `ward exec goose-triage` triages open issues with a **pluggable judgment engine** (default local Goose+`qwen3-coder:30b`, or `--engine claude` / a `command` judge for a stronger re-triage): P0 net + confirm, urgency run-off cut into P0-P4, plus an **automation-mode** axis (`headless`/`interactive`/`consult`), applied as forgejo labels via `ward ops forgejo` (ward-kdl). Default-engine judgments route through `ward exec goose-json` ([goose-failure-records.md](goose-failure-records.md)).
- [Backlog loop](backlog-loop.md) - `ward exec backlog-loop` is the backbone for a **supervised ralph loop** over a repo's open backlog: reads the goose-triage tier + mode labels, ranks open issues into a `headless` auto-burndown lane and an `interactive` surface-to-human lane, dispatches `ward agent headless`, polls `docker ps` for exits, and parses a `WARD-OUTCOME:` blocker comment so a human can unblock stuck agents and re-dispatch. Spans a multi-repo **scope** (`--repo a/b,c/d`): select / next / poll aggregate one ranked view across the set in a single invocation (agentic-os#279). Durable ledger under `~/.cache/agentic-os/backlog-loop/`, one per repo. The supervised foreground form of the heartbeat loop (agentic-os#237). Driven via the [tooling-backlog-loop](../.agents/skills/tooling-backlog-loop/SKILL.md) skill.
- [Cross-repo tooling and release](features-release-tooling.md) - pre-commit baseline, diagnostic helpers, Forgejo-canonical release actions.
- [dev-base container image](dev-base-image.md) - the inner-loop toolchain (uv, pre-commit, node, go, aws cli, claude, codex, goose) published per release to the forgejo registry as `coilyco-flight-deck/agentic-os:<tag>`, multi-arch, pulled by tag in ward. Bakes a **public substrate seed** (bare mirrors of the image-tier reference repos at `/opt/substrate-seed`) so a ward container warms a cold gitcache with no network. Bakes the **in-container agent self-name** (a trimmed `agent-name.sh` under `/opt` plus a policy-tier `/etc/claude-code/managed-settings.json`) so a warded explorer / headless agent self-names like a host session, uid-independently ([agentic-os#281](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/281)). A scheduled [**auto-bump**](dev-base-auto-bump.md) (`.forgejo/workflows/dep-bump.yml`, `ward exec dep-bump`) resolves each pinned tool against upstream and commits one `ARG` bump per stale tool to main, republishing `:latest` so the image stops drifting behind upstream.
- [Managed AGENTS.md pointer block](features-agents-pointer.md) - org-aware, drift-checked workspace-base pointer rendered into each repo's AGENTS.md.
- [Encoded leak guard](leak-guard.md) - pre-commit hook that rejects plaintext occurrences of awkward-leak terms (employer/partner names, private-to-public references) held as hex and decoded only in memory, so the ruleset is not itself grep-bait.
- [Context-budget report](context-budget.md) - on-demand measure of the eager startup context each harness (claude/codex/opencode) loads vs a per-harness token budget, with per-source attribution, reusing the agent-compose resolution.
- [Mount-eligibility manifest](mount-eligibility-manifest.md) - agent-compose emits `mount-eligibility.json`: per harness, the repos it may mount on this host (`~/projects/<org>/<repo>` paths plus an always-on default set), reusing the composer's scope/harness selection so ward reads the mount decision instead of re-deriving it. Drift-checked.
- [Committed ward-ops reference](ward-ops-forgejo-reference.md) - checked-in `ward ops forgejo describe` render so operator-verb names stay greppable. `ward exec gen-ward-ops-reference` regenerates it. See agentic-os#261.
- [Claude transcript failure drain](claude-transcript-drain.md) - `ward exec claude-drain` sweeps `~/.claude/projects/**/*.jsonl` and converts Claude Code tool-use failures (`is_error` results - Bash exit codes, client-validated `<tool_use_error>`s, MCP errors, subagent/sidechain transcripts) into schema-v1 failure-records in the same per-repo buffer Goose's `ask()` writes ([goose-failure-records.md](goose-failure-records.md)), so the o11y feed is harness-complete. Claude Code hooks can't see tool failures (PostToolUse is success-only, the Bash payload has no exit code, some errors fire no hook), so the transcript JSONL is the source. A per-file byte watermark makes a re-sweep idempotent; an expected-non-zero classifier flags benign `grep`-no-match / `|| true` failures so genuine ones are not buried. No network (the GlitchTip shipper is a separate issue). See agentic-os#249.
- [Knowledge-base freshness program](knowledge-base-freshness.md) - grades knowledge by **decay-class** (asserted/pointer/derived) and **half-life** (fast/slow), carried inline as `<!-- freshness: as-of= half-life= -->` provenance markers. `ward freshness` parses them across tracked docs and flags any fact aged past its horizon (`-- --check`), the loud trigger a scheduled probe (`.forgejo/workflows/freshness.yml`) fails on, since knowledge rot is silent where code drift is loud. Hermetic, time-based, not a commit-path hook. See agentic-os#262.
