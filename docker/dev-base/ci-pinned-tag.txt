# CI-in-dev-base pinned tag: the single dev-base image tag every app's CI job
# runs against, so a green CI means "a headless agent can land this" rather than
# "it passed in some other environment" (agentic-os#328).
#
# This is the source of truth. An app does NOT fetch this at CI time (config is
# never fetched downward). An ansible/template rollout in infrastructure reads
# this value and templates it into each app's .forgejo/workflows/*.yml as a
# literal `container:` tag, per the authoring-vs-rollout law. See
# docs/ci-in-dev-base.md.
#
# Pinned, not :latest, on purpose: adopting a newer dev-base is a deliberate
# bump here (which re-validates every app on the next rollout), not silent
# drift. Bump this line to a newer published tag, then let the rollout fan it
# out. Published tags come from the release pipeline (docs/dev-base-image.md).
#
